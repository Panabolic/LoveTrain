# 2026-10-06 살점 HUD / 조직 창조

## 승인 및 범위

사용자는 대화 견본을 반복 수정한 뒤 “이대로 구현해서 게임에 적용하자”로 구현을 승인했다. Mode는 Implementation이며 씬/직렬화 연결 변경은 High, 기능은 Leaf UI이다.

- 기존 오른쪽 아래 위치, 영혼 상단, 실제 살점 수량, 가변 제작 비용을 누적 계산한 중첩 게이지.
- 빨주노초파남보 + 분홍·청록·백색을 순환. 창조 후에는 남은 살점과 새 비용으로 다시 계산한다.
- 게이지 바로 아래 `F 조직 창조`와 현재 비용. 2회 이상은 `조직 창조 X N`, 1회는 `조직 창조`.
- 별도 제작 횟수, 추가 1회 안내, 잔여/비용 분수는 삭제한 최종 견본을 따른다.
- 구현 중 추가 지시: 살점·영혼 글자는 라벨과 숫자 모두 같은 크기(12 logical px)로 표시하며 두 줄의 오른쪽 끝을 맞춘다.
- 실제 장비 슬롯과의 겹침 확인 후 사용자는 게이지와 박스를 줄이는 해결을 명시했다. 우측 20/하단 17 여백을 유지하며 박스 150×92, 게이지 130×11 logical px로 축소한다.
- 경제 수치·보상·실제 창조 거래·F 입력·다른 HUD·새 Manager·패키지·ProjectSettings·저장 계약 변경은 금지 범위다.

## 검증

- 실제 계산 소스 메모리 컴파일: 경계 19건 + 독립 반복 지불 비교 1,000건 통과. `outputs/flesh-hud-preview/math-validation-result.txt`.
- 전체 런타임 134개 소스 및 Editor 소스 MSBuild 컴파일 오류 0. 새 파일을 포함하는 task 전용 복제 csproj를 사용하고 Unity 생성 csproj는 수정하지 않았다. MSBuild에는 기존 API/미사용 필드 및 Inspector 직렬화 필드의 미할당 경고가 존재한다.
- 원본 Editor에서 신규 소스/타입 임포트 및 씬 연결을 수행했다. 원본에 별도 batchmode를 실행하지 않았다.
- 실제 원본 소스·씬을 재사용한 격리 Unity 6000.2.3f1에서 동일 폰트/우측 경계 검사까지 포함한 356개 Editor 메서드/씬 검사와 UI-only 렌더 10장 통과. 참조/누락 스크립트, 105→75→35, 색 순환, F 상태, 캐시 무효화·구독, KO/EN, 큰 횟수 20,721의 글자 폭, 1920×1080/1280×720/1024×768 안전 영역을 검사했다.
- `outputs/flesh-hud-preview/unity-hud-validation-result.txt`, `unity-hud-compact-render.log`, `unity-hud-*.png`에 최종 축소 상태의 증거를 저장했다. UI-only 렌더는 게임 월드 캡처와 구분한다.
- 실제 격리 Junmo PlayMode 36개 검사 통과: 실제 OnEnable/Awake/Start, 보상 이벤트, 비용30→40→50/살점105→75→35, 모드 전환, 재활성화, 언어 변경, 공식 Dynamic Input System의 가상 F→기존 Update/UI 큐→작업대 열기/실제 닫기 애니메이션/복귀.
- 처음에는 숨겨진 batch Game View의 키보드 입력 경계 때문에 가상 F가 timeout되었다. fixture만 임시 InputSettings 복제본과 공식 Dynamic 업데이트로 조정했고, 게임의 F 입력/패키지/설정은 바꾸지 않았다. 최초 실패 증거를 `unity-hud-play-first-attempt.txt`/`unity-hud-play-first-console.txt`에 보존했다.
- 실제 PlayMode의 장비 슬롯 10개와 CurrencyHUD 좌표를 비교했다. 최초 넓은 패널은 슬롯 1/9와 겹쳤으며, 사용자 지시대로 폭을 줄인 최종 상태에서는 겹침 0이고 Wheel 슬롯 우측과 8 logical px 간격이다. 위치를 옮기거나 장비 HUD를 수정하지 않았다.
- 최종 `unity-hud-play-validation-result.txt`/`unity-hud-compact-play.log`에서 새 HUD 및 다른 월드 오류 0을 확인했다. 기존 DDOL/StartObject warning은 별도 console에 보존했다. batch ScreenCapture의 전체 게임 PNG 생성은 지원되지 않아 미실행으로 구분하며 UI-only 렌더와 실제 PlayMode 좌표 증거를 사용했다.
- `scene-audit.json`으로 기존 로컬 fileID 보존과 허용 영역만의 변경을 확인했다. 변경한 소스/씬의 git diff 공백 검사 통과.
